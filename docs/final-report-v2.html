二、独立审查发现的问题（全部修复）

P0：metrics_middleware 异常路径崩溃 P0

根因：'response' in dir() 判断不可靠，call_next 抛异常时 response 未定义，response.headers 报 UnboundLocalError，且异常路径无指标无追踪头。
修复：重写 dispatch，status 默认 500，try/finally 记录指标，response 存在才注入头。复验：401 异常路径 errors=1 正确记录。

P1：熔断器在账号不可用时误标成功 P1

根因：record_success 在 fetch_remote_info 返回后立即调用，但返回的账号可能不可用（限流/无配额），导致熔断器把不可用账号误判为健康。
修复：record_success 移到 _is_image_account_available 确认后；返回成功但不可用记为 record_failure。复验：state 流转正确。

P1：SSE 客户端断开协程泄漏 P1

根因：event_generator 的 while True 无客户端断开检测，异常时静默 pass 死循环，客户端断开后协程持续运行泄漏。
修复：外层 try/except asyncio.CancelledError，客户端断开时正常退出协程。

P1：use-version-check 仍访问 GitHub 远程 P1

根因：内部定制化部署仍会 fetch GitHub 远程 VERSION/CHANGELOG，离线环境报错。
修复：改为仅使用构建时注入的本地版本，移除远程 fetch 与 toast。复验：无 GitHub 引用。

P1：header-actions/version-dialog GitHub 链接被还原 P1

根因：之前去除的 GitHub 链接被覆盖还原。
修复：重新去除 header-actions 的 GitHub 链接和 version-dialog 的"前往 GitHub 更新"按钮。

P2：ProxyPoolConfig 未使用导入 P2

修复：移除冗余导入。

四、变更测验（测测你是否理解）

终局审计测验

1. metrics_middleware 的 P0 bug 根因是什么？

A. 变量名拼错   B. 'response' in dir() 判断不可靠且异常路径 response 未定义   C. 缩进错误
B. dir() 返回模块级名字不含局部变量，call_next 抛异常时 response 未定义导致 UnboundLocalError，且异常路径无指标无追踪头。修复：status 默认 500，try/finally 记录，response 存在才注入头。

2. 熔断器 P1 bug 是什么，为什么危险？

A. record_success 在账号不可用时调用，误判不可用账号为健康   B. 熔断次数太少   C. 冷却时间太长
A. record_success 在 fetch_remote_info 返回后立即调用，但返回的账号可能限流/无配额不可用。危险在于熔断器把不可用账号误判为健康，破坏熔断保护。修复：移到可用性确认后，返回成功但不可用记为失败。

3. SSE event_generator 泄漏问题是什么，如何修复？

A. 内存泄漏   B. 客户端断开后协程无检测持续运行，加 CancelledError 处理   C. 数据太大
B. while True 无客户端断开检测，客户端断开后协程继续推数据泄漏。修复：外层 try/except asyncio.CancelledError 正常退出。

4. 品牌定制漏掉了哪个组件仍访问 GitHub？

A. header-actions   B. use-version-check（仍会 fetch 远程 VERSION/CHANGELOG）   C. top-nav
B. use-version-check 仍会 fetch GitHub 远程 VERSION 和 CHANGELOG，离线/内部部署报错。修复：改为仅本地构建时注入的版本。

5. bat 闪退的三重根因是什么？

A. UTF-8 BOM + LF 行尾 + 中文 GBK 损坏   B. 端口占用   C. 缺少 pause
A. UTF-8 BOM（cmd 把 EF BB BF 当命令）、LF 行尾（cmd 只认 CRLF 错切命令）、UTF-8 中文在 GBK 下损坏。修复：GBK + CRLF + 无 BOM。
