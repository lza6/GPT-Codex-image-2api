三、验证测验（测测你是否理解全部变更）

生产级增强测验

1. 熔断器在什么条件下从 CLOSED 转为 OPEN？

A. 任何一次失败   B. 连续失败 5 次   C. 累计失败 10 次   D. 30 秒无请求
B. 连续失败达到阈值（默认 5 次）触发熔断，防止请求排队打到坏账号雪崩。

2. 每个响应带哪两个头用于请求追踪和延迟统计？

A. X-Forwarded-For / X-Real-IP   B. X-Request-ID / X-Response-Time-Ms   C. ETag / Cache-Control
B. X-Request-ID 用于按 ID 串联调用链，X-Response-Time-Ms 显示该请求处理耗时。

3. TLS 连接池复用解决什么问题？

A. 内存泄漏   B. 每次请求新建 Session 导致 TLS 握手开销 ×N   C. 账号被封
B. Session 池按代理配置缓存并复用 TCP/TLS 连接，避免每次 TLS 握手，降低高并发下的延迟尾巴。

4. SSE 端点为什么需要支持 ?token= 查询参数鉴权？

A. 更美观   B. EventSource 无法设置 Authorization header   C. 提升性能
B. 浏览器 EventSource API 不支持自定义请求头，所以通过 ?token= 查询参数传递 auth-key。

5. 日志自动清理的触发条件和裁剪策略是什么？

A. 每次写入都裁剪到一半   B. 每 200 条检查一次，超 5000 裁剪到 3000   C. 每天定时清空
B. 惰性触发（每 200 条检查一次避免高频 I/O），超过 5000 条时保留最新 3000 条。

6. config.json schema 校验在什么时候执行，拦截哪些错误？

A. 保存时校验所有字段   B. 启动时校验关键配置类型（枚举/整数/非负）  C. 不校验
B. 启动时校验 scheduler_mode 枚举值、workers/rate_limit 等整数类型与非负，JSON 语法错误给出行号列号。
