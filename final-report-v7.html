2. 核心直觉：本轮最重要的三个判断

判断一：「已闭环」最多的地方，恰恰是假闭环密度最高的地方

前六轮每轮都宣称熔断/池化/前端体验"闭环"。本轮六路审计实证发现：

  • Session 池化是假闭环——接线确实完成（S2 核验为真），但 OpenAIBackendAPI.__init__ 往共享池 Session 写 Authorization，实证复现：b1 实例的请求头携带 b2 实例的 token。池化"接上了"但"接错了"，六轮没抓到是因为没有任何测试构造过"同 key 两实例"的场景。
  • resume-poll 是假闭环——OpenAIBackendAPI(proxy_url=...) 调用即 TypeError（形参不存在），该路径六轮零测试。
  • SSE 是假闭环——从 localStorage 读 token，但会话存在 localforage（IndexedDB），恒为 null，流通道从未建立，只有 30s 轮询兜底在工作。
方法论推论：「组件存在 + 接线完成 + 测试全绿」三者同时成立，仍不等于行为正确。必须构造"最不利场景"做实证（本轮：同 key 两实例、调用即崩的路径、存储真实位置）。

判断二：防线必须工具化，否则审计结论随会话蒸发

用户要求"契约防坑/压测/慢查询/SQL/测试有效性"不是一次性审计，而是可持续执行的回归。本轮把五道防线固化为脚本 + 一键执行器，并立即自证价值：

contract_guard 首跑 → 抓 1 断链假功能（前端调 /api/proxy 后端从未注册） → 修复 → 断链 0
mutation_probe 首跑 → 熔断默认阈值 5→6 变异逃逸（测试全用自定义阈值） → 补 2 条回归测试 → 3/3 caught

判断三：多 worker 守卫必须不可绕过

bat 与 Dockerfile 此前直接 uvicorn main:app，绕过 main.py 的 workers 回退与 prometheus multiproc 初始化——CHATGPT2API_WORKERS=4 在这两条生产路径上静默无效。修复方式不是改 bat/Docker，而是把守卫模块级化：让任何启动路径都经过同一个 resolve_workers()。这类"把部署约束编码进启动路径而非靠文档"的模式已写入 ADR-007 与黄金范例。

10. 验收测验（必过）

以下 10 题覆盖本轮全部关键决策与证据。展开答案自查——全对才算理解本轮变更。

Q1. Session 池化串号的根因是什么？修复的三件套是什么？

  1. A. 池 key 不含账号标识；修复 = key 加 token 末 8 位
  2. B. __init__ 往共享 Session 写 Authorization；修复 = 池 key 加 fp 标识 + Authorization 请求级 + fp 从 token 确定性派生
  3. C. Session 没有 close；修复 = finally close
查看答案
B。实证：同 key 两实例，b1 请求头带 b2 的 token。A 是第六轮已修（不够），C 会拆连接。修复后实证：不同 token 不同 Session、池上无 Authorization、同 token 复用。

Q2. resume_poll 六轮零测试放过了什么 bug？为什么零测试？

  1. A. 超时太短；因为没压测
  2. B. OpenAIBackendAPI(proxy_url=...) 调用即 TypeError（形参不存在）；因为该路径无任何测试覆盖
  3. C. 代理不生效；因为没配代理
查看答案
B。调用处传 proxy_url 关键字 vs __init__(self, access_token="")——Python 必然 TypeError。test/ 全目录 grep resume_poll 零命中，解释六轮绿测为何漏。这是"覆盖率看着够但一上线就崩"的教科书案例。

Q3. bat/Docker 的 workers 配置为什么静默无效？修复方式为什么不选"改 bat 加 --workers"？

  1. A. bat 语法错误；改 bat 就够了
  2. B. bat/Docker 直跑 uvicorn main:app 绕过 main.py __main__ 守卫；改守卫模块级化让两条路径共享 resolve_workers()，而非在 bat 里复制守卫逻辑
  3. C. uvicorn 不支持 workers；换 gunicorn
查看答案
B。守卫（JSON 回退 + multiproc 初始化）在 __main__ 块，uvicorn CLI import main 时不经过。把部署约束编码进启动路径（模块级）而非靠文档/启动器复制——ADR-007 + 黄金范例 #7。

Q4. JSON 存储的"监控全绿丢账号"事故链是什么？修复的两个语义是什么？

  1. A. 磁盘满；修复 = 加磁盘监控
  2. B. 损坏文件 _load_json_list 静默 return [] + health_check 只读不解析报 healthy；修复 = 原子写（tmp+replace）+ 损坏抛错/health_check 解析校验
  3. C. 并发写；修复 = 加锁
查看答案
