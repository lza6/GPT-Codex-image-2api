1. 上下文

v2.0.0 终局审计留下 19 项登记缺口（D1–D19），原计划部分登记 v2.2。本轮用户指令"不登记，全部闭环"——按优先级分 8 个阶段全量收口，覆盖安全边界、韧性盲区、可观测性缺口、主动告警、多 worker 架构、测试有效性六大维度。

2. 直觉与关键判断

直觉 1：池化改造必须首尾呼应。 D6 codex 从 urllib 改 curl_cffi 池化，我改了请求发起侧（session.post）却漏了响应消费侧（raw.read()）——curl_cffi Response 根本没有 read()。红队用一行真实 curl_cffi 调用复现：成功路径 100% AttributeError。教训：迁移库时，消费侧的每一个方法调用都要对着新库的真实 API 逐个核对，不能假设同名存在。

直觉 2：mock 凭空创造方法 = 测试在撒谎。 codex 测试之所以全绿，是因为 MagicMock 默认接受任何属性访问——resp.read() 在 mock 上"合法"，在生产对象上不存在。修复不是改生产代码就完事，而是把 mock 改 spec 限定（只暴露真实接口），让"误用不存在方法"在测试期就炸。mock 应该逼近真实依赖，而不是迎合实现。

直觉 3：不可证的承诺比不承诺更危险。 D16 我最初在 docstring 写"限流误差 <5%"，但固定窗口近似在窗口边界数学上允许 2× 突刺——这个承诺在代码层面不可证，测试也没覆盖边界。红队逼我降级为诚实表述："跨 worker 计数一致，边界允许最多 2× 突刺"。宁可写清取舍，不写漂亮假话。

直觉 4：去重指纹字段不全会误抑制。 告警 5 分钟去重是防风暴，但指纹只取 4 个字段时，同一账号"refresh_401 失效"和"密码重登失败"两条不同语义的告警会互相吞掉。补全 reason/trigger/plan_type/source_type 后，语义不同即指纹不同。去重的粒度必须细到能区分"真正不同的事件"。

直觉 5：惰性清理在高频路径要节流。 进度字典 prune 挂在 get 路径（SSE 每秒轮询），记录数大时每次全扫是 CPU 浪费。但简单加 60s 节流会让 TTL 语义失真（过期记录多活 60s）。折中：>100 条才节流，小规模全扫保精确。性能优化不能以牺牲语义正确性为代价，要找到两全的阈值。

7. 变更测验（必须全部答对）

Q1：红队抓到的 Critical 1 是什么，根因和修法？
答案：b。D6 把 urllib 请求改成 session.post，但 _iter_codex_response_events 仍调 raw.read()——curl_cffi Response 只有 .text/.content。测试 MagicMock 默认接受任何属性造成假绿，改 spec=["status_code","headers","text","content"] 后误用 read() 会在测试期炸。
Q2：为什么说"mock 凭空创造方法 = 测试在撒谎"？
答案：c。MagicMock() 对 resp.read() 不报错，但 curl_cffi Response 没有 read()——测试全绿掩盖了生产必崩。spec 限定让 mock 只暴露真实接口，误用立刻失败。mock 的职责是模拟真实依赖，不是迎合实现。
Q3：限流共享层的"误差 <5%"为什么被降级？
答案：a。固定窗口（incr + TTL 按 window_slot 分桶）在边界处攻击者可在 1 秒内打满两个窗口的配额——误差上界是 100% 而非 5%。诚实表述改为"跨 worker 计数一致，边界允许最多 2× 突刺"，精确滑窗（Redis ZSET）登记后续迭代。
Q4：告警去重指纹为什么要补 reason/trigger/plan_type/source_type 字段？
答案：d。5 分钟去重防告警风暴，但指纹只有 token_suffix 时，同一账号 5 分钟内两种不同失效原因只发一条——运维看不到失效原因演变。去重粒度必须细到能区分"真正不同的事件"。
Q5：prune 节流为什么设计成">100 条才启用 60s 窗口"而不是全量启用？
答案：b。简单 60s 节流会导致 get 路径过期记录不被及时清理（TTL 语义破坏，测试红）。折中：记录数 >100 时（全扫成本高的场景）启用节流防退化，≤100 时全扫保语义精确。性能优化不能牺牲语义正确性。
Q6：v2.1.0 新部署为什么要先 cp config.example.json config.json？
答案：c。config.json 含弱密钥且被 git 跟踪是安全隐患（D1），治理后只入库脱敏的 config.example.json。新部署必须 cp 并改 auth-key，README 快速开始已补该指引（红队 R3 发现的文档缺口）。
