### 2.3 导入后账号池状态

**更正**：之前报告里写"6 个异常"是某时间点快照，实际深度排查后真实分布如下（直接读 `data/accounts.json` 原始数据，避开日志中文渲染问题）：

| status | 数量 | 说明 |
|--------|------|------|
| 正常 | 24 | 全部有 refresh_token，可自动续期；quota 分布 3/5/24/25 |
| 异常 | 73 | 全部 `token invalidated (/backend-api/me)`，refresh_token **全为空**，token 失效后无法续期 |
| 待登录 | 5 | pending:{email} 占位，凭据保留，不参与调度 |
| **合计** | **102** | pending 不计入 list_tokens 调度池 |

**根因深挖（异常 73 个）**：

| 维度 | 发现 |
|------|------|
| 错误信息 | 73 个**完全一致**：`last_refresh_error = "token invalidated (/backend-api/me)"` |
| refresh_token | 73 个**全为空**（0/73）→ token 失效后无法走 OAuth 续期 |
| access_token | 72 个非空（失效的旧 JWT） |
| password | 69 个有 → 可走 re-login 密码恢复 |
| source_type | 72 个 web（老导入），1 个 password（本轮 cjbwfowtfoojv 成功登录拿到 access_token 但没拿到 refresh_token） |
| invalid_count | 46–60（累积失效次数，多次刷新都失败） |

**结论**：这 73 个异常不是本轮导入导致的，是**老账号 token 失效后因无 refresh_token 无法自动续期**被上游判 invalid。本轮新导入成功 1 个（cjbwfowtfoojv）也因 OpenAI 对这批 outlook 免费账号**不发 refresh_token**（风控）而迅速失效。

### 2.4 re-login 重试链路（对异常账号实测）

对 5 个有 password 的异常账号调 `POST /api/accounts/re-login`：

| 账号（匿名） | 结果 | 说明 |
|-------------|------|------|
| #1 | need_verification_code | 密码对，但需邮箱 OTP |
| #2 | need_verification_code | 密码对，但需邮箱 OTP |
| #3 | need_verification_code | 密码对，但需邮箱 OTP |
| #4 | password_verify_failed_401 | 密码错 |
| #5 | need_verification_code | 密码对，但需邮箱 OTP |

**关键发现**：本项目的 `_login_with_password` 是**纯 HTTP 实现**，遇到 OpenAI 要求邮箱 OTP 验证码就返回失败（`need_verification_code`）。这批 outlook 账号被 OpenAI 风控要求 OTP，所以 re-login 也失败。

要恢复这批账号需走**浏览器 + 邮箱取码**流程（参考项目 `GPT自动化注册的项目/scripts/revive_import.py` 有完整实现：98faka 邮箱 API + Playwright 过 CF + OTP），本项目未集成该能力。

## 8. 核心结论

### 8.1 本项目侧（全部 OK）

- ✅ 账号密码导入 `邮箱----密码` 格式完整兼容
- ✅ 自动登录抓 Token（复用 `_login_with_password`）
- ✅ 失败保留待登录凭据（`pending:{email}` 占位，可 re-login）
- ✅ 负载均衡轮询调度（6 次图片请求调度到 6 个不同账号）
- ✅ pending 账号不污染调度池（`list_tokens` 过滤）
- ✅ 文本 API 正常（29s 返回）
- ✅ 前端导入对话框 + E2E 10/10 PASS

### 8.2 上游侧（非本项目 bug）

- ⚠️ 文生图/图生图对所有 outlook 免费账号统一返回 `File link not found.` 502
- 这是 ChatGPT 官网对 outlook 免费账号图片生成权限的风控/降级信号（同类反向项目也报这个）
- 文本 API 正常证明账号本身有效，仅图片权限被限

### 8.3 异常账号根因（73 个）

| 问题 | 原因 | 是否本项目 bug |
|------|------|---------------|
| token invalidated | refresh_token 全为空 → 失效后无法自动续期 | 否（OpenAI 对 outlook 免费账号不发 refresh_token 风控） |
| re-login 失败 | OpenAI 要求邮箱 OTP，`_login_with_password` 纯 HTTP 无法过 | 否（需浏览器+邮箱取码流程，本项目未集成） |
| password_verify_failed_401 | 密码本身错（少数） | 否 |

### 8.4 中文乱码说明

- `data/accounts.json` 数据本身是**正确的 UTF-8**（`status="正常"` 字节为 `e6 ad a3 e5 b8 b8`）
- 日志/控制台显示 `????` 是 **Windows GBK 控制台渲染问题**，非数据错误
- 通过 API 读取字段值正常，仅终端直接打印中文时乱码

### 8.5 后续建议

- 这批 outlook 账号文本可用，图片权限被限
- 要图片可用需换有图片权限的账号（Plus/Team 或非 outlook 账号）
- 或走注册项目（`GPT自动化注册的项目`）的浏览器流程重拿带图片权限的 token
- 73 个异常账号恢复方案：集成浏览器+邮箱取码的 OTP 流程（参考 `revive_import.py`），或直接重新注册新账号
