### 2.3 导入后账号池状态

**更正**：之前报告里写"6 个异常"是某时间点快照，实际深度排查后真实分布如下（直接读 `data/accounts.json` 原始数据，避开日志中文渲染问题）：

| status | 数量 | 说明 |
|--------|------|------|
| 正常 | 24 | 全部有 refresh_token，可自动续期；quota 分布 3/5/24/25 |
| 异常 | 73 | 全部 `token invalidated (/backend-api/me)`，refresh_token **全为空**，token 失效后无法续期 |

| **合计** | **102** | pending 不计入 list_tokens 调度池 |

**根因深挖（异常 73 个）**：

| 维度 | 发现 |
|------|------|
| 错误信息 | 73 个**完全一致**：`last_refresh_error = "token invalidated (/backend-api/me)"` |
| refresh_token | 73 个**全为空**（0/73）→ token 失效后无法走 OAuth 续期 |
| access_token | 72 个非空（失效的旧 JWT） |
| password | 69 个有 → 可走 re-login 密码恢复 |
| source_type | 72 个 web（老导入），1 个 password（本轮 cjbwfowtfoojv 成功登录拿到 access_token 但没拿到 refresh_token） |
| invalid_count | 46–60（累积失效次数，多次刷新都失败） |

**结论**：这 73 个异常不是本轮导入导致的，是**老账号 token 失效后因无 refresh_token 无法自动续期**被上游判 invalid。本轮新导入成功 1 个（cjbwfowtfoojv）也因 OpenAI 对这批 outlook 免费账号**不发 refresh_token**（风控）而迅速失效。

### 8.2 上游侧（非本项目 bug）→ 更正：图片 502 是本项目下载链路 bug

**深度排查后更正**：之前判断"图片 502 是上游 outlook 账号图片权限被限"是错的。真实根因如下。

#### 8.2.1 图片生成其实成功了

实测日志证实：图片**生成成功**，拿到了 `file_id` 和 `sediment_id`，并解析出了下载 URL：

```
[INFO] image_poll_hit_no_settle: file_ids=["file_000000005cfc81f4..."], sediment_ids=[同]
[DEBUG] image_urls_resolved: urls=["https://chatgpt.com/backend-api/estuary/content?id=file_...&sig=..."]
[WARNING] image_stream_fail: "image_download failed: status=404, body={\"detail\": \"File link not found.\"}"
```

生成 OK，下载 URL 也拿到了，**失败在最后一步：GET estuary URL 下载图片字节时 404**。

#### 8.2.2 真实根因：下载 estuary URL 没带 web cookies

对比 `GPT web端的逆向注意参考我的这个/下载图片的接口.txt` 真实抓包：web 端下载 `estuary/content` URL 时携带**完整 cookies**（`oai-did`/`oai-sc`/`cf_clearance`/`_cfuvid`/`__Secure-next-auth.session-token`/`_uasid`/`__cflb` 等全套）+ `referer: https://chatgpt.com/c/{conversation_id}` + `if-modified-since`/`if-none-match`。

本项目 `services/openai_backend_api.py:2762 download_image_bytes`：
```python
def download_image_bytes(self, urls: list[str]) -> list[bytes]:
    for url in urls:
        response = self.session.get(url, timeout=120)  # 只带 session 默认头（JWT Bearer + 指纹头）
        ensure_ok(response, "image_download")
```

session 池化时只注入了 `OAI-Device-Id`/`OAI-Session-Id` + Bearer JWT，**没有 web 端跑完 CF 挑战+登录后的 cookies**（`cf_clearance`/`_cfuvid`/`oai-sc`/`__Secure-next-auth.session-token` 等）。estuary/content 被 Cloudflare/estuary 层判定无有效会话 → 返回 `{"detail":"File link not found."}` 404。

#### 8.2.3 账号密码登录拿不到 token 的根因

本项目 `services/account_service.py:_login_with_password` 是**纯 HTTP 实现**（PKCE + password/verify + sentinel），遇到：
- OpenAI 邮箱 OTP 验证码（`need_verification_code`）→ 直接返回失败
- Cloudflare 挑战 → 无法过

实测 5 个异常账号 re-login：3 个 `need_verification_code`、1 个密码错、1 个 OTP。这批 outlook 账号被 OpenAI 风控要求 OTP，纯 HTTP 无法过。

参考项目 `GPT自动化注册的项目/scripts/revive_import.py` 有完整方案：Playwright 浏览器过 CF + 98faka 邮箱 API 取 OTP + 提交，本项目未集成。

#### 8.2.4 解决方案

| 问题 | 方案 | 工作量 |
|------|------|--------|
| 图片下载 404 | `download_image_bytes` 带 web cookies（`cf_clearance`/`_cfuvid`/`oai-sc`/`__Secure-next-auth.session-token`）+ `referer: chatgpt.com/c/{cid}` | 小（改 1 个方法） |
| 账号密码 OTP | 集成浏览器+邮箱取码流程（参考 `revive_import.py`：Playwright + 98faka/91kami 邮箱 API） | 大（新增子服务） |
| CF 挑战 | 同上浏览器方案 | 大 |
