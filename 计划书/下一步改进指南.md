# ChatGPT2API 下一步改进指南（v2.8.1 → v3.x · v4.x · v5.x）

> **定位**：本文件是本项目「计划书」文件夹的核心迭代蓝本，供任何 AI 或开发者据此刻画下一个版本。
> 每一章都是「现状（真实代码依据）→ 问题 → 方案 → 落地步骤 → 验收标准 → TDD 清单」的完整闭环。
> **禁止假实现**：每一条落地后必须跑通测试、五道防线、E2E，并在 `workflow_status.md` 登记证据。
>
> - **基线版本**：v2.8.1（2026-08-05，410 测试全绿 / 五道防线全 PASS / 契约断链=0 / E2E 10/10）

> - **总原则**：不重构没坏的东西、不重复造轮子；每个改进独立可回滚；旧产物清理归档（见 `archive/`）。

### 1.4 真实瓶颈分析（第一性原理）

1. **账号存活仍是产品核心价值**：号池可用率 > 一切。调度/熔断/寿命预测/告警/探活/审计/密码导入已围绕它建闭环，但「自动化处置」（自动降级、自动重登、自动隔离、失败凭据一键重试）仍多为半自动。
2. **安全纵深已补审计，但 auth-key 仍单值**：v2.8.0/v2.8.1 补齐管理操作留痕 + 登录留痕 + 凭据导入；`auth_service.py` 已存在但仅单 key 校验 + 弱口令检测，**无多 key 列表 / 无宽限期轮换 / 无角色细分**——这是当前最大的安全短板。
3. **可观测性：指标齐全、日志已结构化落盘 + request_id 已全链路追踪，但缺字段过滤入口**：`log_service._structured_item` 已 json.dumps 落盘，`request_id` 已三处注入 detail（:112-120, :174-179, :583-601，从 `metrics_service.get_request_id()` contextvar 取，全链路追踪一致），`request_context.py` contextvar 已被中间件+审计+鉴权消费。**唯一真实缺口**：`/api/logs` 仅支持 `type/start_date/end_date/account_email/days`，**缺 `request_id=`/`event=`/`model=` 字段过滤**——写入端闭环，读取端未闭环。`/metrics` 鉴权已就位但缺调度选取分布/寿命风险分布/熔断状态转移等高级指标。
4. **架构演进空间**：3 大后端文件仍超 1800 行（openai_backend_api 2977 / account_service 2144 / conversation 1886）；协议接入仍是改主类；多实例部署无指南。
5. **前端体验已到 8 成**：异步按钮/骨架/分页/审计 tab/账号密码导入已落地，但 image-manager 787 行无虚拟滚动、深色主题对比度未系统排查、无国际化骨架（约束：内部中文使用，优先级低）。
6. **运维自愈仍半自动**：bat 崩溃重启已带指数退避，但无崩溃摘要落盘、无 5 次熔断后人工介入提示、无依赖健康自检端点（`/health` 仅返回静态状态，不探存储/Redis/上游连通）。

## 3. P0 · 安全纵深（v3.3）

> 目标：把「单一 auth-key + 已留痕」升级为「可轮换 + 多 key + 全量脱敏」，补齐 v2.x/v2.8.x 安全边界的剩余短板。
> **关键修正**：旧版文档建议「新增 services/auth_service.py」——但该文件 v2.8.1 **已存在**（单 key 校验 + 弱口令检测）。本版方案是**增强既有文件**，非重写。

### 3.1 auth-key 轮换 + 多 key 列表（核心安全短板）

**现状分析（真实代码依据）**：
- 认证仅一个 `auth-key`，用环境变量 `CHATGPT2API_AUTH_KEY` 覆盖（services/config.py:286 `_normalize_auth_key` / :453 getter）。
- `services/auth_service.py` 已存在但仅做单 key 校验 + 弱口令检测（`_warn_if_weak_auth_key`），**无多 key 列表、无宽限期、无轮换端点**。
- config.py 启动时 production 拒绝弱口令，但没有「定期轮换提醒」。
- token 轮换逻辑已有（account_service:567 `rotated = new_token != old_token` + 熔断器孤儿清理），可复用「宽限期内双值并存」思路。

**问题**：
1. key 泄露后只能人工改配置 + 重启，无审计追踪（虽有 require_admin 埋点，但轮换动作本身无端点）。
2. 无「新旧双 key 宽限期」，轮换时调用方全部瞬间 401。
3. 多调用方共用单 key 时无法按 key 区分用量/审计 operator。

**方案（增强 auth_service.py，不重写）**：
1. `config.py` 支持 `auth_keys: list[str]`（兼容 `auth-key` 单值，`_normalize_auth_keys` 归一化为列表；环境变量 `CHATGPT2API_AUTH_KEYS` 逗号分隔覆盖）。
2. `auth_service.py` 增强：校验时遍历列表，命中任一即通过；记录命中的 key id（用于审计 operator 与用量分组）。
3. 新增 `POST /api/system/rotate-auth-key`（require_admin，审计自动留痕 v2.8.0 埋点）：生成新 key → 写配置 → 旧 key 进宽限期（`auth_key_grace_seconds`，默认 3600）→ 过期移除。
4. 前端设置页 user-keys-card 增强：显示 key 列表 + 命中 key id + 轮换按钮 + 宽限期倒计时。
5. 轮换事件自动入审计日志（rotate 端点天然 require_admin）。

**落地步骤**：
- [ ] `config.py` 支持 `auth_keys` 列表（兼容 `auth-key` 单值，归一化） + `auth_key_grace_seconds` 配置项（六步链路全做）。
- [ ] `auth_service.py` 增强：多 key 校验 + 命中 key id 返回 + 宽限期状态机（内存态 + 启动时从配置恢复）。
- [ ] `api/system.py` 新增 rotate-auth-key 端点（require_admin + 幂等 + 审计留痕）。
- [ ] 前端 user-keys-card 增加轮换 UI（复用既有卡片模式，禁造轮子）。
- [ ] 契约守卫 --update + E2E 断言（轮换后新 key 可用、旧 key 宽限期内可用、过期拒绝）。

**验收标准**：
- [ ] 轮换后新 key 立即可用，旧 key 宽限期内可用，过期后拒绝（401）。
- [ ] 重复轮换不产生脏状态（幂等：相同请求第二次返回已存在）。
- [ ] 轮换动作在审计日志有记录（v2.8.0 埋点自动覆盖，operator 末 8 位脱敏）。
- [ ] 契约断链=0 + 全量测试绿 + 五道防线 PASS。

**TDD 清单**：
- [ ] `test_auth_rotation.py`：单值→列表归一化 / 多 key 命中任一通过 / 宽限期内新旧双可用 / 过期旧 key 拒绝 / 重复轮换幂等 / 环境变量 `CHATGPT2API_AUTH_KEYS` 逗号分隔覆盖优先 / 命中 key id 入审计 operator。

### 3.2 敏感信息全量脱敏（加固）

**现状分析（真实代码依据）**：
- token 展示层已末 8 位（accounts 页），审计 operator 已脱敏（v2.8.0 `_mask_operator`）。
- 但需系统排查日志/告警/响应/异常 msg 中的暴露面：`detail.account_email` 在日志逐条落盘——邮箱本身不算高危，但需确认**没有完整 access_token 落盘**。
- `anonymize_token` 已存在（account_service:583 调用），可抽为统一工具函数。

**方案**：
1. 全仓 grep `access_token` 写日志/告警/响应/异常 msg 的暴露点，统一脱敏（保留末 8 位约定，抽 `utils/token_mask.py::mask_token()`，复用 audit_service._mask_operator 与 account_service.anonymize_token 思路，**禁造轮子**——先确认既有函数可复用）。
2. `alert_service.py` 告警正文、`backup` 快照、`config` 序列化、`/api/settings` 响应中凡含 token 的字段一律脱敏。
3. 新增 `mask_token` 工具 + 全量断言测试；既有 `anonymize_token` 若签名兼容则直接复用而非新造。

**落地步骤**：
- [ ] grep 全仓 access_token 暴露点（`rg "access_token" services/ api/ -l`）。
- [ ] 抽/复用 `mask_token` 工具（优先复用既有 anonymize_token，仅在不兼容时新造）。
- [ ] 告警/备份/响应/异常 4 处统一脱敏。

**方案**：`list()` 改 `seek` 尾部倒读分块（复刻 utils/log.py `_SafeStreamHandler` 经验，`errors='replace'` 兜底）。量级突破 10w 行/天再启动。
**触发条件**：单天日志文件 > 10MB 或 > 10w 行。

### 8.2 账号存储增量写

**现状**：json_storage save_accounts 整文件覆写 O(N)。当前量级 <1k 无感。
**方案**：量级突破 1w 前不做；届时切 SQLite（已支持，scripts/migrate_storage.py 已存在），不在 JSON 上做增量写（避免造轮子）。

### 8.3 前端 bundle 瘦身

**现状**：dashboard 引入 recharts（大库）；image 页可能整包引 lucide。
**方案**：recharts 改具名导入 / 动态 import（`next/dynamic`）；lucide 已树摇（确认）；`next/dynamic` 拆分首屏。
**验收**：`web/out` bundle 体积对比 + Lighthouse 首屏指标（有证据才报，不跑全量 Lighthouse）。

## 10. 工程质量门禁（每批次必过）

### 10.1 测试策略

- 单元 + 集成 + E2E 三层次；覆盖率目标：**新增逻辑 ≥90%，关键模块（调度/熔断/连接池/日志/告警/审计/鉴权）向 100% 冲刺**。
- 活测试（live/redis 标记）不触网，本地手动 `uv run pytest -m live`。
- 变异探针是「测试真能抓住回归」的守门员：任何新逻辑必须能通过种子变异被抓，否则补测试。

### 10.2 五道防线（scripts/run_all_guards.py）

| 防线 | 通过标准 |
|------|---------|
| 契约守卫 | 断链=0，漂移=0（改字段先 --update） |
| SQL 安全审查 | 注入面/事务/多 worker 守卫 0 告警 |
| 慢查询猎杀 | 本轮热点从清单移除（附报告） |
| 变异探针 | caught ≥ 6，escaped=0 |
| 极限施压 | 并发突刺 + 慢存储注入 + 并发写一致性 PASS |

### 10.3 E2E 冒烟

前端改动跑 `scripts/e2e_smoke.cjs`；新增交互反馈断言持续扩展。真实浏览器 + 真实服务，禁 mock 充数。**改前端后必须同步 web_dist**（`rm -rf web_dist && cp -r web/out web_dist`），bat 仅在 web_dist 缺失时构建。

### 10.4 终局交付门禁

- [ ] 需求追踪：workflow_status.md 有矩阵行 + 证据
- [ ] 反向批判：至少攻击 3 个假设并修复
- [ ] 假功能扫描：前端按钮/开关/菜单必有真实后端调用证据（契约断链=0）

### 10.5 盲区扫描（每轮至少一次）

1. 最苛刻验收：哪个功能「界面上有、流程走不通」

## 12. 版本规划执行建议

1. **v3.3（安全纵深）+ v3.4（可观测性）优先开工**：二者风险低、无依赖、价值立现——审计日志已闭环（v2.8.0），密钥轮换是最后一个安全短板；结构化日志已落盘（v2.6.0），字段过滤 + Trace 关联是 v4.0 拆分与 v5.x 智能化的前提。
2. **v4.0（架构演进）其次**：大文件拆分必须在行为快照测试就位后动手，每抽一个模块跑一次全量（用户约束：不要大幅度重构，严格按切片 + re-export 零破坏）。
3. **v5.x（产品/智能/前沿）最后**：依赖 v4.0 的地基，且部分项（多模型路由/AI 审核）需评估真实需求，避免过度工程。
4. **每批顺序**：先 TDD 写测试锁定行为 → 实施 → 全量回归 → 防线 → 文档同步 → 登记 workflow_status。
5. **禁止**：为赶进度跳过防线或 E2E；大文件拆分必须「每抽一个模块就跑一次全量」，不允许一次性大搬移。
6. **保持可回滚**：每个子项独立提交，commit message 遵循 Conventional Commits（feat/fix/refactor/chore + 描述）。
7. **清理旧产物**：每版发版后清理 `reports/` 与 `final-report-*.html` 等中间产物，保持仓库只留最新版本；旧版指南归档到 `计划书/archive/`（已归档 v2.8.0 旧版）。
