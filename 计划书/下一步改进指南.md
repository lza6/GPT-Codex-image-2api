# ChatGPT2API 下一步改进指南（v1.9.0 → v2.0.0）

> 创建时间：2026-08-02
> 更新状态：已根据 Unreleased 实际落地内容二次核验重写
> 适用版本：当前 v1.9.0 + Unreleased（8 项生产级增强已闭环）
> 本文档性质：**只出计划与修改指南，不含代码实现**。交由执行方按阶段落地，每阶段附 TDD 清单与验收标准。
> 核心约束（必须遵守）：
> 1. **不大幅度重构任何文件**——只在现有基础上修改、改进、迭代；禁止重写、重建。
> 2. **不重复造轮子**——动手前先检查项目内是否已有实现（services/、api/、web/），优先改造现有模块。
> 3. **先修 bug 再加功能**——严格按本文档阶段顺序执行，禁止跳跃。
> 4. **每阶段必须闭环**——测试跑通 + 实际运行验证 + 更新 docs/workflow_status.md 后才算完成。
> 5. **清理旧产物**——每次升级后删除被替代的旧代码/旧文件/旧配置，不留屎山残留。

## 第一部分：项目现状评估（事实基础）

### 1.1 架构现状

```
客户端 → FastAPI (api/) → services/protocol/（协议适配层）
                            ↓
                     services/openai_backend_api.py（上游调用，2763 行）
                            ↓
                     services/account_service.py（号池调度，1850 行）
                            ↓
                     services/storage/（json / sqlite / postgres / git 四后端）
前端：Next.js 16 + React 19 + Tailwind 4 + zustand（web/，构建产物 web_dist/）
```

- 入口：`main.py` → `api/app.py`（lifespan 管理 3 个守护线程：account-watcher / image-cleanup / backup）
- HTTP 客户端：`curl_cffi.requests.Session`（同步），FastAPI 侧用 `run_in_threadpool` 包装
- 已落地中间件：`MetricsMiddleware`、`RateLimitMiddleware`、`CORSMiddleware`
- 已落地韧性组件：`services/circuit_breaker.py`（熔断）、`services/session_pool.py`（连接池）、`services/metrics_service.py`（指标）
- 测试：37 个测试文件、177 个测试函数（pytest + httpx/TestClient；`ls test/test_*.py | wc -l` = 37，`grep -c "def test_" test/*.py` 求和 = 177）
- 压测基线：4 Worker 7912 req/min（docs/PLAN.md 记录）

## 第二部分：改进总目标（v2.0.0 定义）

**一句话：从"单机可用 + 部分生产级增强"升级为"全链路生产可信"——分布式状态可共享、安全边界可兜底、质量门禁可自动、前端体验可闭环。**

| 维度 | v1.9.0 + Unreleased 现状 | v2.0.0 目标 | 度量 |
|------|------------|------------|------|
| 分布式状态 | 单进程内存（Redis 未实现） | Redis 可选接入（不装 Redis 时完全回退现有行为） | 4 Worker 限流计数误差 < 5% |
| 韧性覆盖 | 熔断/连接池/指标已声明，集成度未验证 | 全上游调用点 100% 走熔断 + 池化 + 指标 | 模拟上游 5xx 风暴时 P99 延迟不翻倍，且日志可见熔断事件 |
| 安全 | CORS 宽松默认、无请求体限制、无安全头 | 生产模式默认收紧 + 启动安全检查清单 + 请求体大小分级限制 | 默认配置通过安全基线检查（test_security.py 扩展用例全绿） |
| 质量保障 | 手跑测试、无 CI | CI 四道门（lint/type/test/security）+ 活测试标记隔离 | 每次提交自动跑纯单测，CI 通过率 100% 且不触网 |
| 前端体验 | dashboard 有 SSE，其他页面手动刷新 | logs/accounts/settings 关键操作实时反馈 + 统一 toast/loading + request-id 展示 | 抽查 10 个写操作按钮，全部有 loading + 结果 toast + 错误带 request-id 后 8 位 |
| 可维护性 | 三巨文件 2763/1850/1644 行 | 温和拆分至各 <1200 行（提取式，不改行为） | import 路径对外零变化，测试全绿 |

### 阶段 2：Redis 可选共享状态（P0，2.5 天）——让多 Worker 名符其实

**目标**：消除 S1。**设计原则：Redis 是可选增强，不装 Redis 行为与现状完全一致**（零依赖回归风险）。

- [ ] 2.1 **抽象共享状态层**（**新建 services/shared_state.py**，<200 行）
  - 接口定义（Protocol 或 ABC）：
    - `incr_window(key: str, window_seconds: int) -> int`（限流计数，返回当前窗口内计数）
    - `next_index(key: str, modulo: int) -> int`（轮询游标，原子自增取模）
    - `cache_get(key: str) -> bytes | None`、`cache_set(key: str, value: bytes, ttl: int) -> None`（聊天缓存）
  - 双实现：
    - `LocalSharedState`（现有内存逻辑原样搬入：deque 滑动窗口、dict 缓存、itertools.count 游标）
    - `RedisSharedState`（redis-py + Lua 脚本保证滑动窗口原子性；缓存用 SETEX；游标用 INCR + MOD）
  - 工厂函数 `get_shared_state()` 按 `REDIS_URL` 环境变量选择；连接失败自动降级 Local 并打 WARNING（**不允许因 Redis 挂了导致服务不可用**）
  - 依赖：`redis` 包加入 pyproject.toml（可选 extras：`pip install chatgpt2api[redis]`）
- [ ] 2.2 **限流中间件迁移**（api/rate_limit.py）：
  - 计数器改用 `get_shared_state().incr_window()`，行为不变
  - 多 Worker 下全局限流终于准确（当前 4 Worker = 阈值 ×4 的 bug 修复）
- [ ] 2.3 **调度轮询游标迁移**（services/account_service.py `self._index`）：
  - round_robin 模式游标走 `get_shared_state().next_index()`
  - 注意：健康档位评估仍各进程独立（复杂度高，本轮不做跨进程同步，文档注明）
- [ ] 2.4 **聊天缓存迁移**（services/protocol/chat_completion_cache.py）：
  - 后端可切换到 Redis（带 TTL），Local 实现保留
  - 缓存 key 增加前缀 `chatgpt2api:cache:` 避免与其他应用冲突
- [ ] 2.5 **docker-compose.yml 增加可选 redis service**（profile 隔离，默认不启动）：
  - `docker-compose --profile redis up` 才启动 redis
  - .env.example 增加 `REDIS_URL` 注释说明（格式、可选、降级行为）
- [ ] 2.6 **配置项**：`redis_url`（默认空 = Local）、`redis_max_connections`（默认 10）、`redis_socket_timeout`（默认 5s）

## 第四部分：风险与权衡（提前说清）

| 决策 | 权衡 | 理由 |
|------|------|------|
| Redis 做可选而非必选 | 多一层抽象成本 | 大量用户单机跑 bat，强制 Redis 会提高门槛；Local 回退保零回归 |
| 活测试标记移出 CI | 覆盖率数字下降 | 触网测试在 CI 必然 flaky；本地手动跑保留（`pytest -m live`），CI 门禁必须稳定 |
| 熔断器/连接池已落地但需核验集成度 | 可能发现部分路径未覆盖 | CHANGELOG 声明与实际代码可能有偏差，阶段 0 核验是必要的前置步骤 |
| 巨型文件拆分而非重写 | 收益渐进 | 遵守"不大幅重构"红线；提取式拆分风险最低，测试即安全网 |
| /metrics 需鉴权 | 多一步配置 | 指标含账号规模等敏感信息，公网裸奔不可接受 |
| conversation.py 拆分延后到 v2.1 | 1644 行仍超 800 行红线 | 协议层逻辑复杂，拆分风险高于收益，先保证 openai_backend 和 account_service 拆完 |
| CORS 默认收紧是 breaking change | 老用户升级后跨域失效 | 安全 > 便利；README Upgrade 章节醒目标注，配置项保留 `["*"]` 能力 |
